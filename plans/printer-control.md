# Printer control: thumbnails, sending prints, live status

## Goal

Close the gap between "FarmSlicer produces G-code" and "the print is running on
a printer". FarmSlicer should take over everything the maintainer's earlier
print-station app does for Bambu Lab printers (that app only accepts
pre-sliced `.gcode.3mf` files), and do it for files FarmSlicer slices itself:

1. Thumbnails rendered for every slice, embedded in the G-code and in the
   `.gcode.3mf` package, with an optional per-group label/logo overlay (for a
   league of numbered teams: the team number).
2. Send a sliced job (or an uploaded pre-sliced `.gcode.3mf`) to a printer and
   start it; watch it run; pause/resume/stop; keep a print history.
3. Live printer status (state, progress, temperatures, AMS trays, errors).
4. Split nozzle selection from machine model on the Slice page.
5. LAN discovery that demonstrably works and coexists with other listeners.

## Environment / context

  `FARMSLICER_SKIP_CXX=1 cargo check` / `tests/run-e2e.sh` with
  `CARGO_TARGET_DIR` set. Web: `cd web && bun run build` works locally.
- The worktree's `extern/OrcaSlicer` submodule is not checked out (local
  reference clone failed: "Unable to find current revision"); read libslic3r
  sources from the main checkout's submodule (pristine v2.4.2).
- Production runs with host networking (`network_mode: host`) on buildhost,
  which sits in the same /20 as the farm's printers, so SSDP broadcasts can
  reach it.
- Bambu LAN access needs the printer's access code and serial; the old app
  also requires LAN-only + Developer Mode on the printers.

## Decisions already made (don't re-ask)

- **The repo never contains the maintainer's farm settings.** Tuned profiles
  live in the database (`custom_profiles`), created through the UI.
- **Nozzle selection is split from the model** on the Slice page (the Printers
  page already does Manufacturer → Model → Nozzle).
- **Thumbnails are generated by FarmSlicer**, with an optional label/logo
  overlay. The overlay is a generic group setting; nothing league-specific in
  code.
- **Replicate the old print station's printer features** in FarmSlicer.
- Nothing deployment-specific (host names, domains, IPs, league names) is
  committed here (public repo).

## Design

### Packaging and thumbnails (C++, `cxx/slice_core`)

- libslic3r's `Print::export_gcode(path, result, thumbnail_cb)` takes a
  `ThumbnailsGeneratorCallback`; we pass `nullptr` today. Supply a **software
  rasteriser** in slice_core (z-buffer, flat/Lambert shading in the filament
  colour, iso camera fit to the placed model's bbox, supersampled, transparent
  background). Same code runs natively and in wasm, so both engines produce
  identical images.
- Package the `.gcode.3mf` with libslic3r's own `store_bbs_3mf`
  (`Format/bbs_3mf.hpp`), exactly like the GUI's "send to printer" path
  (`Plater::send_gcode`: strategy `Silence | SkipModel | WithGcode |
  SkipAuxiliary`, one `PlateData` with `gcode_file`, md5, `thumbnail_file`,
  prediction/weight, `slice_filaments_info` from
  `PlateData::parse_filament_info(&gcode_result)`, `printer_model_id`,
  `nozzle_diameters`; filament type/colour/id filled from config). This gives
  printers the `slice_info.config` they use for AMS mapping and the preview.
  `printer_model_id` (e.g. `N1`) lives in the vendor's `machine_model` JSON,
  not the merged config: Rust passes it in.
- Overlay: drawn in slice_core onto the rendered thumbnail so both engines
  agree. Text via stb_truetype (header-only; check what OrcaSlicer vendors)
  with a font from OrcaSlicer's `resources/fonts`; logo PNG decoded with
  libslic3r's PNG reader. Inputs come in a new `SliceOptions` struct next to
  `config_json` (label text, logo bytes, printer_model_id).

### Printer link (Rust, new `src/bambu/`)

- `mqtt`: one task per configured printer: MQTTS 8883, user `bblp`, password
  = access code, cert verification off (printers use a Bambu-CA cert; LAN
  only), stable client id, subscribe `device/<serial>/report`, publish
  `device/<serial>/request` QoS 1, `pushall` on connect. Reconnect with
  backoff. Printer CRUD restarts that printer's task (the old app needed a
  service restart).
- `status`: keep the report as a JSON value and **deep-merge** each `print`
  delta into it (P1/A1 send partial reports). Command echoes update nothing
  but the pending-command waiters. Staleness watchdog → offline.
- `ftps`: minimal async implicit-FTPS client on tokio-rustls (port 990,
  USER/PASS, PBSZ 0, PROT P, TYPE I, PASV, STOR). **The data channel must
  resume the control channel's TLS session** (vsftpd: `522 SSL connection
  failed: session reuse required`): share one `ClientConfig` and server name.
- `commands`: `project_file` with the real plate gcode path, md5, subtask
  name and AMS mapping; pause/resume/stop/`print_speed` (param is a string);
  `gcode_line` for preheat/cooldown; ack waits keyed by `sequence_id`, retry
  while the printer indexes a fresh upload.
- Browser push: SSE stream of printer status.

## Findings / gotchas

From a full read of the old print-station app (protocol facts and its bugs,
which we must not copy):

- MQTT: `mqtts://<ip>:8883`, user `bblp`, password access code,
  `rejectUnauthorized: false`, keepalive 30 s. Topics `device/<serial>/report`
  (sub) and `device/<serial>/request` (pub, QoS 1). `pushall` =
  `{"pushing":{"sequence_id":"0","command":"pushall"}}`.
- Start command used: `{"print":{"command":"project_file","param":
  "Metadata/plate_1.gcode","project_id":"0","profile_id":"0","task_id":"0",
  "subtask_id":"0","subtask_name":"","file":<name>,"url":"ftp://<name>",
  "md5":"","bed_type":"auto","timelapse":false,"bed_levelling":true,
  "flow_cali":true,"vibration_cali":true,"layer_inspect":false,
  "use_ams":…,"ams_mapping":[…]}}`. Old-app bugs: plate hard-coded to 1, md5
  and subtask_name empty, a timeout counted as success.
- Printers need a moment to index a freshly uploaded file: retry the start (old
  app: 3 tries, 2 s apart, 5 s ack wait).
- Ack matching: response `print.command == "project_file"` and same
  `sequence_id` (or none); success = `result == "SUCCESS"` or `gcode_state`
  RUNNING/PREPARE.
- Firmware reports `subtask_name` as `"project_file"` or empty for LAN starts;
  the real file is in the echo's `url` (`file:///sdcard/<name>`).
- FTPS: implicit TLS on 990, user `bblp`; upload to SD root `/<name>`.
  Session reuse is mandatory on the data channel (Bun couldn't do it, hence
  the old app's Node subprocesses).
- Old app rebuilt status from scratch on every message, so P1/A1 deltas and
  command echoes reset fields; deep-merge instead.
- AMS tray global id = `unit.id * 4 + tray.id`; colours `RRGGBBAA`. H2D AMS
  units carry `info[0]` = nozzle (1 left, 2 right). External spool 254/255 and
  AMS-HT ids 128+ exist; the old app ignored them.
- Old app's AMS mapping matched type only and ignored the user's tray choice.
- Camera: RTSP on 322 for X1-class; A1/P1 use a TLS JPEG stream on port 6000.
- SSDP model codes: `3DPrinter-X1-Carbon`/`3DPrinter-X1`/`BL-P001`/`BL-P002`
  → X1C, `3DPrinter-X1E`/`C13` → X1E, `C11` P1P, `C12` P1S, `N1` A1 mini,
  `N2S` A1, `H2D`/`O1D` H2D (O1D unverified), `H2C`, `H2S`, `P2S`.
- A 25 s listen on buildhost's UDP 1990/1900 saw no printer NOTIFYs (only our
  own M-SEARCH loopback). Printers announce on 2021, which production FarmSlicer
  holds without `SO_REUSEADDR`, so it couldn't be checked from outside the
  process; production discovery is unverified until it logs sightings.

### Sending details (from OrcaSlicer's GUI source)

- `ams_mapping` (v0): one entry per project filament (0-based filament
  index), value = global tray id (`unit*4+slot`), `-1` for unused filaments
  and for external spools. `ams_mapping2` (v1): one
  `{"ams_id", "slot_id"}` per filament, `255/255` for unused
  (`SelectMachineDialog::get_ams_mapping_result`). `use_ams` false when only
  external spools are used. Send both.
- The `project_file` JSON itself is built by Bambu's closed network plugin;
  field list from the old app and community docs (see Findings).
- `project_file` ack: `result` "FAIL" means failure (DeviceManager.cpp).
- Bambu model ids (machine_model JSON `model_id`): A1 mini `N1`, A1 `N2S`,
  H2D `O1D`, H2D Pro `O1E`, H2S `O1S`, P1P `C11`, P1S `C12`, P2S `N7`,
  X1 Carbon `BL-P001`, X1 `BL-P002`, X1E `C13`, X2D `N6`. Read them from
  the profiles, don't hard-code.
- Compatibility: same model and nozzle; X1/X1 Carbon/X1E and P1P/P1S are
  interchangeable (the old app's rule).
- SD file name: `<model name>-<print id prefix>.gcode.3mf`, unique, so
  matching reports to our print is unambiguous and stale thumbnails can't
  happen.
- A stopped print reports `gcode_state` FAILED with `print_error`
  0x0300400C ("cancelled") — to verify on hardware.

## Open questions for the user

1. Who may send prints, and to which printers? Recommendation: a group setting
   `printers` (allowed printer ids, inherited down the tree) plus a site-wide
   default; admins always.
2. May a dev instance connect to the real printers read-only (MQTT status) for
   testing? Later: a test print on a printer you pick, at a time you say.
3. Run both systems side by side during migration? Printers cap concurrent
   LAN MQTT clients (a handful), so each extra client costs a slot.

## Things not to do

- Don't put real host names, IPs, domains or league names in this repo.
- Don't start a print on a real printer without the user's per-print OK.
- Don't copy the old app's bugs listed above.
- Don't hand-roll the Bambu `.gcode.3mf` layout; use `store_bbs_3mf`.
